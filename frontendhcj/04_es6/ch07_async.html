Promise 의 세 가지 상태

상태영문뜻
대기pending아직 결과가 나오지 않은 상태
이행fulfilled성공적으로 완료되어 값이 담긴 상태
거부rejected실패가 확정된 상태
const myPromise = new Promise((resolve, reject) => {
    if (성공) resolve(결과값);      // 이행 상태로
    else reject(에러);              // 거부 상태로
});

myPromise
    .then(result => console.log(result))      // 이행되면
    .catch(error => console.error(error));    // 거부되면

알아두기 new Promise 를 직접 쓸 일은 거의 없습니다. fetch 가 이미 Promise 를 만들어 돌려주기 때문입니다. 중요한 것은 "Promise 를 받으면 then/catch 또는 await 로 결과를 꺼낸다"는 사용법입니다.

then 체인과 async / await

// then 체인
fetch(url)
    .then(response => response.json())
    .then(posts => console.log(posts))
    .catch(error => console.error(error));

// 같은 일을 async / await 로
async function getPosts() {
    try {
        const response = await fetch(url);
        const posts = await response.json();
        return posts;
    } catch (error) {
        console.error(error);
    }
}

키워드뜻규칙
async이 함수는 Promise 를 돌려준다함수 앞에 붙인다
await이 Promise 가 끝날 때까지 기다린다async 함수 안에서만
try / catch기다리다 실패하면 catch 로then 체인의 .catch() 자리
자주 나는 오류 await is only valid in async functions — 함수에 async 를 빠뜨렸습니다.
Promise { <pending> } 가 찍힌다 — await 나 then 없이 Promise 를 그대로 출력했습니다.
body stream already read — 응답 본문을 두 번 읽었습니다. json() 은 한 번만 부를 수 있습니다.
알아두기 fetch 는 404 나 500 응답을 받아도 catch 로 가지 않습니다. "답장을 받았다"는 이유로 이행 상태가 되기 때문입니다. if (!response.ok) throw ... 를 직접 써야 합니다.
