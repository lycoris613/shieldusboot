6장. 폼(form)과 입력 — 3부의 핵심

6장 · 01_HTML_기초.docx

폼의 기본 모양

<form id="studentForm">
    <label for="name">이름:</label>
    <input type="text" name="name" id="name" required />
    <button type="submit">학생 등록</button>
</form>

수강 형태:

빈 칸으로 등록을 눌러 보세요. required 때문에 브라우저가 막습니다.
전화번호를 하이픈 없이 입력해 보세요. pattern 때문에 막힙니다.

input 의 type

type쓰임얻는 것
text이름, 학번, 주소가장 기본
email이메일모바일에서 @ 키보드, 형식 검사
date생년월일달력 UI. 값은 2000-01-01 형식
number나이, 수량위아래 화살표
password비밀번호글자가 점으로 가려짐
checkbox여러 개 선택체크 여부
radio하나만 선택같은 name 끼리 한 묶음

id 와 name — 둘 다 필요한 이유

속성무엇을 위한 이름인가누가 쓰는가
id="name"문서 안에서 이 요소 하나를 특정 CSS 선택자, getElementById, label 의 for
name="name"전송되는 데이터의 키(key) FormData, 서버 요청, studentForm.name
알아두기 id 만 넣고 name 을 빠뜨리면 화면은 멀쩡해 보입니다. 그런데 실습 3-5에서 FormData 로 값을 모으는 순간 그 입력창만 통째로 빠지고, formData.get("address") 가 null 을 돌려주면서 이어지는 .trim() 에서 오류가 납니다.
미니 과제 위 폼에서 이메일 칸의 name="email" 을 지운 뒤 F12 → Network 탭을 열고 등록을 눌러 보세요. 전송 목록에서 email 이 사라진 것을 확인할 수 있습니다.

button 의 type — 빠뜨리면 반드시 사고가 납니다

type동작언제 쓰나
submit폼을 제출한다 (생략 시 기본값)등록 · 저장 버튼
button아무 동작도 하지 않는다취소 버튼, JS 전용 버튼
reset입력값을 모두 지운다거의 쓰지 않음
자주 나는 오류 form 안의 button 은 type 을 안 쓰면 자동으로 submit 이 됩니다. 실습 3-10의 취소 버튼에 type="button" 을 반드시 붙이라고 하는 이유가 이것입니다.

「처음 시작하는 프론트엔드」 기초 문서 예제 · F12를 눌러 개발자 도구를 함께 보세요.
