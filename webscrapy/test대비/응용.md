### 1-2. 데이터 구조 파악 — `info()` / `dtypes` / `describe(include=)`

### 1-3. `loc` vs `iloc` — 이름 기준 vs 위치(정수) 기준
2단계엔 `loc`만 있었는데, **`iloc`(정수 위치 기반)**과의 차이가 실전에서 매우 중요하게 다뤄집니다.
```python
data.loc[20:25]              # 인덱스 '이름'이 20~25인 행 (끝 포함!)
data.iloc[20:25]             # 위치가 20~24번째인 행 (끝 미포함, 일반 슬라이싱과 동일)

data.iloc[20:25, 1:8]        # 행 위치 20~24, 열 위치 1~7
data.loc[[40,55,60], ['인구수','광역시도','행정구역']]   # 특정 인덱스+컬럼명 리스트로 선택

data.loc[:, '인구수':'행정구역']   # loc는 컬럼명 "범위"도 슬라이싱 가능(끝 포함) — iloc는 정수만 가능
```
> **핵심 차이**: `loc`는 "라벨(이름)" 기준이라 슬라이싱 끝이 **포함**되고, `iloc`는 "정수 위치" 기준이라 끝이 **미포함**(파이썬 리스트와 동일)됩니다. *(03)*

### 1-5. `Series.map()` — 값 변환 (내장함수 `map()`과는 다름!)
2단계 내장함수 표에 있던 `map(함수, iterable)`과는 별개로, **pandas의 `Series.map()`**은 컬럼(Series)의 각 값을 변환할 때 씁니다. 두 가지 쓰임이 있습니다.

```python
area_1000['면적2'] = area_1000['면적'].map('{:,}'.format)

# ② 딕셔너리로 값 매핑 (등급 -> 점수, 코드 -> 이름 등)
grade_dic = {"A": 100, "B": 90, "C": 80}
person['score'] = person['grade'].map(grade_dic)
```
*(03, 09)* — 특히 ②번(딕셔너리 매핑)은 **feature engineering(피처 엔지니어링)**에서 자주 쓰이는 핵심 패턴입니다. (예: 넷플릭스 `rating` 컬럼 값을 `age_group`이라는 새 컬럼으로 매핑)

### 1-6. `rename()` — 컬럼명 변경과 `inplace` 개념

## 2. 정규표현식(`re` 모듈) — 완전히 새로운 주제

1·2단계 어디에도 정규표현식이 없었는데, 실전 스크래핑에서는 필수로 쓰입니다.

```python
import re

# 1) 패턴 컴파일 + 치환(sub) : 개행/탭 문자 제거
pattern = re.compile(r'[\n\r\t]')
clean_text = pattern.sub('', dirty_text)          # 매칭되는 문자를 전부 빈 문자열로 치환

# 2) 검색(search) + 그룹(group) 추출 : 문자열 속 숫자만 뽑아내기
matched = re.search(r'(\d+)\);', "playSong('1000002721',37928381);")
if matched:
    song_id = matched.group(1)   # group(0)=매칭전체, group(1)=괄호로 감싼 첫번째 그룹
```
*(04, 05_02)* — `re.compile(패턴)`으로 패턴을 미리 만들어두고 `.sub(바꿀값, 대상문자열)`로 치환하거나, `re.search(패턴, 문자열)`로 찾은 뒤 `.group(n)`으로 괄호로 캡처한 부분만 꺼냅니다. **BeautifulSoup으로 뽑아낸 지저분한 텍스트(개행, 특정 ID 숫자 등)를 정제할 때 거의 항상 같이 사용**됩니다.

## 5. SQLAlchemy 실전 — 2단계는 개념만, 여기는 실제 동작 코드

2단계에서 SQLAlchemy는 "노트북에 없는 개념"으로 분류했었는데, **04번 노트북에 실제 사용 코드 전체**가 나옵니다.

```python
import pymysql
pymysql.install_as_MySQLdb()          # pymysql을 MySQLdb처럼 동작하게 등록(연동)
from sqlalchemy import create_engine

engine = create_engine('mysql+pymysql://아이디:비밀번호@localhost:3306/DB이름?charset=utf8mb4')
conn = engine.connect()

# DataFrame -> 테이블로 저장 (컬럼 타입까지 지정 가능)
import sqlalchemy
table_df.to_sql(
    name='songs100', con=engine, if_exists='replace', index=True, index_label='id',
    dtype={
        'id': sqlalchemy.types.INTEGER(),
        'title': sqlalchemy.types.VARCHAR(200),
        'release_date': sqlalchemy.types.DATE,
        'likes': sqlalchemy.types.BigInteger,
    }
)

# SQL 조회 결과를 DataFrame으로 (파라미터 바인딩으로 SQL Injection 방지)
sql = "select * from songs100 where album like %s;"
album_df = pd.read_sql_query(sql, con=conn, params=('%' + keyword + '%',))

# 연결 정리는 반드시 finally에서
conn.close()
engine.dispose()
```
*(04)* — 새로운 핵심 개념들: **연결 문자열(URL) 형식**(`dialect+driver://user:pw@host:port/db`), `if_exists='replace'`(테이블이 있으면 덮어쓰기, 그 외 `'append'`/`'fail'` 옵션도 있음), `to_sql()`의 `dtype=` 옵션으로 컬럼 타입 직접 지정, `read_sql_query()`의 `params=`로 SQL Injection 방지, 그리고 **`conn.close()` + `engine.dispose()`를 `finally`에서 호출**해 자원을 정리하는 패턴(Selenium의 `driver.quit()`과 같은 맥락).

## 8. 데이터 전처리 — 실무 판단 기준 (개념)

2단계는 `dropna()`/`fillna()`/`interpolate()` **문법**만 다뤘는데, 09번 노트북엔 **"언제 무엇을 쓸지" 판단 기준**이 나옵니다.

| 결측치 비율 | 처리 방법 |
|---|---|
| 5% 미만 | 행/열을 **제거**(`dropna()`) — 데이터 손실이 적어 영향 미미 |
| 5% ~ 20% | 다른 값으로 **대체**(`fillna()`, `replace()`) |
| 20% 이상 | 대체하되, 별도 카테고리로 관리하거나 분석 시 유의해서 사용 |

```python
netflix['country'] = netflix['country'].fillna('No Data')       # 대체
netflix['director'] = netflix['director'].replace(np.nan, 'No Data')  # replace로도 결측치 대체 가능
netflix.dropna(axis=0, inplace=True)   # 결측 행 제거 (원본 변경)

netflix.isna().sum()    # isna() == isnull() : 완전히 같은 함수 (별칭 관계)
```
*(09)* — 참고로 2단계 정리에서 "`replace()`는 결측치 처리에 부적합"이라고 했었는데, 정확히는 **`replace(값1, 값2)`로 일반 값을 바꾸는 용도가 원래 목적**이라 결측치 전용 함수(`fillna`)에 비해 덜 권장되는 것이며, **`replace(np.nan, 값)`처럼 명시적으로 쓰면 결측치 대체도 가능**합니다(09번 노트북 실제 사용 사례). 다만 실무·시험 모두 `fillna()`가 더 표준적인 선택입니다.

## 요약 — 3단계에서 새로 등장한 것 중 특히 중요한 5가지

1. **`loc` vs `iloc`** — 라벨 기준(끝 포함) vs 정수 위치 기준(끝 미포함). 실무·시험 모두 헷갈리기 쉬운 대표 포인트.
2. **`pd.concat()` + `DataFrame.from_records()`** — 반복문으로 행을 하나씩 쌓아 DataFrame을 만드는 표준 패턴 (예전 `.append()`는 최신 pandas에서 삭제됨).
3. **정규표현식(`re` 모듈)** — `re.compile().sub()`로 텍스트 정제, `re.search().group()`으로 문자열에서 원하는 부분만 추출. 스크래핑엔 사실상 필수.
4. **SQLAlchemy 실제 코드** — `create_engine()` 연결 문자열 구조, `to_sql(dtype=)`, `read_sql_query(params=)`, 그리고 `finally`에서 `conn.close()`+`engine.dispose()`.
5. **`inplace=True/False`** — pandas 메서드 전반(`rename`, `dropna`, `reset_index` 등)에 반복되는 공통 개념. "원본을 바꿀지, 결과만 보여줄지"를 결정.
